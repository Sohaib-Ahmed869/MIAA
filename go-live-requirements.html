Before We Can Go Live

The donation platform is built and ready. To switch it on with real payments, we now need five accounts and their credentials set up in MIAA's own name — so that MIAA fully owns the payment accounts, the database, the hosting, and the donor data. Think Studio only needs access to configure and maintain them.

Please set up and send us the following. Each section below has short, step-by-step instructions and a clear list of exactly what to provide.

What We Need Why It's Needed Status
A Stripe keys Card payments — Visa, Mastercard, Amex, Apple Pay, Google Pay Required
B MongoDB database Stores donations, donors, campaigns & event records Required
C AWS account Hosting & infrastructure for the platform Required
D Email sender (SMTP) Sends receipts, confirmations & admin notifications Required
E PayPal keys PayPal as an alternative payment method Recommended

One important note on ownership & security

Every account below should be created under MIAA's own email and billing. This keeps MIAA in full control — payouts land in MIAA's bank account, and access can be revoked at any time.

Please do not send secret keys or passwords in a plain email or chat message. Use the secure method described on the final page.

A · Stripe Keys

Stripe processes all card payments — including Apple Pay and Google Pay. Payouts go straight to MIAA's bank account.

A
Set up Stripe & retrieve your API keys
≈ 15 minutes · stripe.com
Purpose: securely take card donations and event payments, with funds settling directly into MIAA's nominated bank account.
  1. Go to stripe.com and create an account using MIAA's email (or log in to the existing one).
  2. Complete “Activate your account” — enter MIAA's business details (ABN, address), a contact person, and the bank account where payouts should land. Stripe requires this before it will issue live keys.
  3. In the Dashboard, make sure the “Test mode” toggle (top right) is OFF so you're on live data.
  4. Open Developers → API keys (or search “API keys”).
  5. Copy the Publishable key (pk_live_…) and reveal + copy the Secret key (sk_live_…).
Please send us
  • Publishable key — pk_live_…
  • Secret key — sk_live_… (via the secure method on the last page)

Easier alternative: instead of copying the secret key, you can invite us as a team member — Settings → Team → Invite, using the email we provide, with the “Developer” role. We'll then generate and manage the keys ourselves. We handle the webhook setup either way.

B · MongoDB Database

MongoDB Atlas is the cloud database that stores every donation, donor, campaign and event record. Setting it up in MIAA's name means MIAA owns the data outright.

B
Create an Atlas account, organisation & grant us access
≈ 15 minutes · mongodb.com/atlas
Purpose: a secure, managed home for all platform data, owned and billed under MIAA.
  1. Go to mongodb.com/cloud/atlas and sign up with MIAA's email (or Google sign-in).
  2. When prompted, create an Organisation — name it MIA Australia. (An organisation is just the top-level account that holds your projects and billing.)
  3. Inside it, create a Project — e.g. MIAA Donation Platform. You can stop there; we'll build the actual database cluster.
  4. Add a payment card so the production database can run: Organisation → Billing → Add Payment Method. (The free tier is fine to start; we'll advise if a paid tier is needed for the Gala load.)
  5. Give us access: Organisation → Access Manager → Invite to Organisation, enter the email we provide, and assign the “Organisation Owner” (or “Project Owner”) role.
Please send us
  • Confirmation that our email has been invited (we'll accept it)
  • The organisation / project name you chose

That's all — once we're in, we create the database cluster, users, and connection securely on our side. No connection strings or passwords need to be emailed.

C · AWS Account

Amazon Web Services (AWS) hosts the platform — the servers and infrastructure that run the website and donation portal, and that scale up automatically during peaks like the Gala launch.

C
Create an AWS account, add billing & grant us access
≈ 20 minutes · aws.amazon.com
Purpose: reliable, auto-scaling hosting owned and billed under MIAA, so infrastructure costs and control sit with the museum.
  1. Go to aws.amazon.com and choose “Create an AWS Account”. Use MIAA's email as the root account email and a strong password.
  2. Enter MIAA's contact and business details when prompted.
  3. Add a payment card (AWS requires one on file; a small temporary authorisation may appear and is refunded).
  4. Complete phone/SMS verification and choose the “Basic Support – Free” plan.
  5. Once inside the console, give us access. The simplest option: open IAM, create a user for the email we provide, and grant it “AdministratorAccess”. (If you prefer, we can send you exact click-by-click screenshots for this step.)
Please send us
  • Your AWS Account ID (12-digit number, shown top-right in the console)
  • Confirmation the IAM user for our email has been created — or the sign-in link + temporary credentials (via the secure method on the last page)

We recommend the Sydney (ap-southeast-2) region so data and hosting stay in Australia. If setting up IAM feels technical, just create the account and add billing — then contact us and we'll walk you through granting access on a quick call.

D · Email Sender (SMTP)

This is the email address that all automated messages are sent from — donation receipts, payment confirmations, event registration emails, and admin notifications. Donors will see it as the sender, e.g. donations@miaaustralia.org or noreply@miaaustralia.org.

D
Choose a sending address & generate SMTP credentials
≈ 10 minutes · your email provider or Brevo
Purpose: reliable delivery of receipts and confirmations that clearly come from MIAA, improving trust and inbox placement.

What is SMTP? It's the standard way software sends email on your behalf. We plug your SMTP details into the platform, and it can then send from your address automatically.

Option 1 — Brevo (recommended, already used for CRM):

  1. Log in to Brevo (the CRM we're already syncing donors to).
  2. Open the SMTP & API section → SMTP tab.
  3. Copy the SMTP server, port, login, and generate an SMTP key (password).
  4. Under Senders, add and verify the from-address you want (e.g. donations@miaaustralia.org).

Option 2 — Google Workspace / Microsoft 365 (if MIAA email is hosted there): create an app password for the sending mailbox and use your provider's SMTP host/port.

Please send us
  • From-address — e.g. donations@miaaustralia.org
  • SMTP host & port — e.g. smtp-relay.brevo.com : 587
  • SMTP username / login
  • SMTP password / key (via the secure method on the last page)

If you're not sure which address to use, we suggest a dedicated donations@ or noreply@ mailbox so replies and receipts are easy to track. We're happy to advise.

E · PayPal Keys

PayPal is offered alongside Stripe as an alternative way to give. It's recommended but optional — the platform runs on Stripe alone if you'd prefer to add PayPal later.

E
Set up a PayPal Business account & create live API credentials
≈ 15 minutes · paypal.com & developer.paypal.com
Purpose: let supporters donate with their PayPal balance or linked accounts, with funds settling into MIAA's PayPal account.
  1. Go to paypal.com and create a Business account with MIAA's email (or upgrade an existing account to Business).
  2. Complete business verification and link MIAA's bank account for withdrawals.
  3. Go to developer.paypal.com and log in with the same PayPal credentials.
  4. Open Apps & Credentials and switch the toggle to “Live” (not Sandbox).
  5. Click “Create App”, name it e.g. MIAA Donations, then copy the Client ID and Secret.
Please send us
  • Live Client ID
  • Live Secret (via the secure method on the last page)

Make sure the credentials are from the Live tab — Sandbox keys only work for testing and won't take real payments.

Please share secrets securely

Secret keys, passwords and SMTP credentials should never be sent in a plain email, WhatsApp, or chat — those channels aren't safe for credentials.

Instead, please use one of these:

• Prefer invite-based access where offered (Stripe team invite, MongoDB org invite, AWS IAM user) — then no secret ever leaves your account.
• For keys that must be copied, send them via a one-time secure link (e.g. onetimesecret.com) or a password manager share. We're happy to set up a shared vault for you.

Not sure about a step? Don't worry about getting every technical detail perfect — just create the accounts and add billing, then reply to us and we'll jump on a short call to finish the access setup together.
