Setting Up Email With Microsoft 365

The platform needs permission to send receipts and confirmations from MIAA's own email address. This guide walks your Microsoft 365 administrator through it, step by step, and lists exactly what to send us at the end.

What This Is For

Every time someone donates, buys an event ticket, or registers, the platform needs to send them an email — a receipt, a confirmation, a ticket. Those emails should come from MIAA, not from an unfamiliar address, so that donors trust them and they land in the inbox rather than the junk folder.

What is SMTP? It's simply the standard way software sends email on your behalf. You give the platform a mailbox and a password, and it can then send from that address automatically. Think of it as handing over a key to one specific mailbox — nothing else in your Microsoft 365 account is touched.

Because MIAA's email is hosted on Microsoft 365, we can send through Microsoft directly. There are three things your administrator needs to do, and then one short list of details to send us.

Step Time
1 Choose (or create) the mailbox the emails will be sent from ≈ 5 min
2 Turn on Authenticated SMTP for that mailbox ≈ 2 min
3 Create an app password for the platform to use ≈ 10 min
4 Send us the details (securely — see the last page) ≈ 2 min
Please read the note on page 6 before starting. Microsoft is retiring this method of sending at the end of December 2026. It works today and is fine for the Gala Dinner, but there's a longer-term decision to make together — we've set it out plainly so nothing catches MIAA by surprise.

Everything below is done by whoever administers MIAA's Microsoft 365 account — the person who can add users and reset passwords. If that's an external IT provider, this guide can be forwarded to them as-is.

1 · Choose the Sending Mailbox

This is the address donors will see in the “From” line of every receipt and confirmation — for example donations@miaaustralia.org.

1
Pick a licensed user mailbox to send from
≈ 5 minutes · Microsoft 365 admin center
Purpose: gives receipts a clear, recognisable sender that donors trust, and gives MIAA one place to see what the platform has sent.
  1. Decide on the address. We suggest a dedicated one such as donations@miaaustralia.org or noreply@miaaustralia.org, rather than a personal staff mailbox — so it keeps working when people change roles.
  2. If it doesn't exist yet, create it in the Microsoft 365 admin center under Users → Active users → Add a user.
  3. Make sure the account has a licence assigned (any plan that includes Exchange Online email).
  4. Set a password for it and keep that password to hand — you'll need it briefly in Step 3.
Important — this cannot be a “shared mailbox”. Microsoft 365 shared mailboxes are free but have no password and cannot sign in, so the platform can't send through one. It must be a normal licensed user account. If MIAA already uses donations@ as a shared mailbox, please tell us — we'll suggest the cleanest way around it rather than have you undo anything.

Whatever address you choose, the platform can only send as that exact mailbox. If you'd like receipts to appear to come from a different address than the one we sign in with, that's possible but needs one extra permission — just let us know and we'll set it up with you.

2 · Turn On Authenticated SMTP

Microsoft switches this off by default as a security measure. It needs to be turned on for the one sending mailbox — and only that mailbox.

2
Enable Authenticated SMTP on the sending mailbox
≈ 2 minutes · Microsoft 365 admin center
Purpose: allows the donation platform — and nothing else — to sign in to that one mailbox and send mail through it.
  1. Go to the Microsoft 365 admin center (admin.microsoft.com) and sign in as an administrator.
  2. Open Users → Active users and click the sending mailbox you chose in Step 1.
  3. In the panel that opens, select the Mail tab.
  4. Under Email apps, click Manage email apps.
  5. Tick the box for Authenticated SMTP.
  6. Click Save changes.

Leave every other option on that screen exactly as it is. Only Authenticated SMTP needs to change, and only on this one account — Microsoft recommends keeping it off everywhere else, which we'd echo.

If the tick box is greyed out or won't save: it usually means SMTP is switched off across the whole tenant, which is a separate setting an administrator can lift. Don't fight it — send us a screenshot and we'll point your IT provider straight at the setting.

3 · Create an App Password

An app password is a long, randomly generated password that works for one application only. We use it instead of the mailbox's real password, so MIAA's actual password is never stored in the platform and can be changed at any time without breaking anything. It can also be revoked on its own if it's ever no longer needed.

3
Generate an app password for the sending mailbox
≈ 10 minutes · Microsoft 365 admin center & security settings
Purpose: lets the platform sign in to send receipts, without ever holding MIAA's real mailbox password.

First — the prerequisite (admin):

  1. In the Microsoft 365 admin center, go to Users → Active users and click Multi-factor authentication in the toolbar.
  2. Find the sending mailbox in the list and set its status to Enabled.
  3. Open the Service settings tab and make sure “Allow users to create app passwords to sign into non-browser apps” is selected.

Then — generate the password:

  1. Sign in to mysignins.microsoft.com/security-info as the sending mailbox (using the password from Step 1).
  2. Complete the multi-factor setup prompt if it appears.
  3. Click Add sign-in method and choose App password.
  4. Name it something recognisable, e.g. MIAA Donation Platform.
  5. Copy the password that appears and keep it safe. Microsoft shows it once and never again — if it's lost, you simply delete it and create another.
If “App password” doesn't appear as an option, it's almost always because the tenant uses Security Defaults or Conditional Access, which deliberately block app passwords. This is a genuine fork in the road, not a small settings tweak — please stop here and contact us rather than turning security features off. Weakening MIAA's overall account security to enable email sending isn't a trade we'd recommend, and there are better options we can walk through on a call.

Once the three steps above are done, we need the following. Most of it is standard and already filled in below — realistically the only things unique to MIAA are the address and the app password.

Please send us
  • Sending address — e.g. donations@miaaustralia.org

  • App password (via the secure method on the last page — never by plain email)
  • Confirmation that Authenticated SMTP is ticked for that mailbox

Good to know — sending limits

Microsoft 365 caps this method at roughly 30 messages per minute and 10,000 recipients per rolling 24 hours. For donation receipts and event confirmations — sent one at a time, as they happen — that is comfortably more than MIAA will ever need, including on Gala night.

It is not suitable for bulk newsletters or mass campaigns to the whole donor list. Those should go out through a proper marketing tool, which keeps MIAA's mailbox reputation clean and protects the deliverability of the receipts that really matter.

One Thing To Be Aware Of

We want to be upfront about this rather than have it surface later. The method in this guide — signing in with an app password — is something Microsoft has announced it is retiring. It works today, and it will comfortably carry MIAA through the Gala Dinner. But it has a known end date, and it's better that MIAA hears that from us now.

When What Microsoft has said will happen
Now → Dec 2026 No change. App passwords and SMTP work exactly as described in this guide.
End of Dec 2026 Switched off by default for existing accounts. An administrator can still switch it back on.
Second half of 2027 Microsoft expects to announce a final date after which it stops working altogether.

What this means in practice. Nothing needs to happen before the Gala. Around November 2026, we'll come back to MIAA with a recommendation and handle the switch — most likely moving to a modern sign-in method that doesn't use a password at all, or to a dedicated sending service. Either way it's our job to manage, not something MIAA needs to track.

Why we're not simply recommending the modern method today

Honestly: time. The modern approach requires registering an application in MIAA's Microsoft tenant and granting it permissions — a heavier piece of work needing coordination with whoever administers your Microsoft 365. With the Gala Dinner on 25 July 2026, the app password route gets MIAA live and taking donations now, with a clear plan to move before Microsoft's deadline.

If MIAA would prefer to go straight to the long-term setup and skip this interim step, we're glad to — just say the word and we'll scope it. It's a longer setup, not a harder one.

Sending It To Us Safely

Please don't send the app password by email or chat

An app password can send email as MIAA. Plain email, WhatsApp and chat apps keep copies on servers and in backups indefinitely — they simply aren't built for credentials.

Instead, please use one of these:

• A one-time secure link such as onetimesecret.com — paste the password in, send us the link, and it destroys itself once we've opened it.
• A password manager share. We're happy to set up a shared vault for MIAA.
• Read it to us over the phone, if that's easiest.

If a password is ever sent somewhere it shouldn't have been, it's no drama — delete it in Microsoft 365 and create another. That's exactly why we use app passwords rather than the real one.
